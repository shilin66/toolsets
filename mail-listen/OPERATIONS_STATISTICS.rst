运营统计
========

页面与权限
----------
桌面端 /admin/operations（1280px 起），入口在“割接任务”下方。
首页展示运营指标、最近八周趋势和重点运营商，运营商明细按 20/50 条分页查询。
普通用户仅统计 can_operate 邮箱，管理员可查看全部；邮箱清空返回空结果，越权筛选返回 403。
概览、供应商汇总、业务明细、导出使用同一邮箱范围。
页面不再展示“统计口径与待确认项”或历史缺口提示，能够从记录统计的指标直接显示数量。

数量与周期
----------
* 接收邮件按邮件记录 ID 计数；割接邮件以识别类型为“割接通知”为准。
* 上报邮件按来源邮件去重，全部关联任务上报成功后计入；上报工单按 carrier_ticket_no 去重，
  全部关联任务成功后计入。部分成功不把其他已完成邮件、工单或线路的数量置空。
* 线路按工单号＋线路编号去重。客户线路展开 circuits 的电路代号；骨干线路展开
  backbone_circuits 中割接对象的系统名称。一封邮件可包含多条线路，重试不重复累计。
* 工单跨供应商重复时仍按工单号去重，归到当前邮箱范围内最早来源邮件对应的供应商；
  业务明细沿用该归属，避免汇总与明细数量不一致。
* 邮件、任务和线路以首次成功时间归属统计周期，工单以全部关联任务完成时间归属周期。
  失败、进行中、未上报记录不计入成功数量。
* 业务明细中的邮件、工单集合与概览数字一致。缺少编号的记录不推造编号；不影响其他可统计数量。
* 回复按成功发送日志逐次计数；旧数据从现存成功回复时间补录，重启不重复补录。
* 当前待处理任务不受查询开始日期截断。

已有记录的兼容读取
------------------
1. 上报数据优先使用队列快照，其次使用统计快照；旧记录没有快照时，使用关联任务中
   已有的工单号、线路类型和填报结果。线路类型已切换时，不把新类型的线路套用到旧上报中。
   现有快照即使内容为空，也不会被当前可变任务覆盖。
2. 成功记录的日期优先取 completed_at，其次取结果中的 resolved_at/updated_at，
   最后使用原上报记录创建时间。SQLite 生成的无时区上报创建时间按 UTC 转为北京时间。
   不使用启动时间补造历史上报时间，不让上周或更早的记录干扰本周结果。
3. 旧任务只有 reported 状态且完全没有上报日志时，可在“所有环境”下根据任务记录统计，
   使用任务更新时间（其次创建时间）。存在失败日志时不据此推造成功记录。
4. 上报环境优先取队列、执行身份或结果中已保存的环境字段；旧结果可根据 final_url
   与配置的登录/会话地址源匹配。只有唯一匹配才确定环境，不根据当前默认环境推断历史。
   无法归类的记录仅进入“所有环境”；默认选择“所有环境”，生产与测试筛选不会互相混入。
5. 正式配置存在即视为已接入。已有配置的首次接入时间使用其创建时间补录并保留；
   后续修改、删除重建不重复计为新增。新配置从首次创建正式配置时累计，草稿不计入。

这些兼容查询不改写上报结果或任务业务状态。已有记录被删除后不再参与统计；
旧任务没有提交快照时，线路数量依据其现存填报记录，不是不可变历史审计账本。
无时区的邮件、任务、配置及回复时间沿用系统的北京时间约定。

运营商范围
----------
运营商与监听邮箱尚无独立关联表，邮箱筛选下按历史来件关联。
管理员全局范围可以看到没有来件的正式配置；普通用户仅看到所选操作邮箱关联的运营商。
未知发件地址单列数量，不假设一个发件地址就是一家运营商。
总供应商数量未确定，不输出全量供应商覆盖率；仅在来件归属明确时显示来件接入率。

验证
----
接口用例覆盖权限、空筛选、跨邮箱去重、旧记录兼容、日期边界、环境识别、快照优先、
多线路、重复上报、部分成功、供应商归属、配置首次创建、回复次数及 CSV 导出。
规模用例含 321 个正式配置、10,002 封邮件、3,001 个成功工单，本机汇总约 0.35 秒。
浏览器通过真实 Flask/SQLite 验证 1280/1440 桌面、旧记录数量、筛选、分页、明细和导出。
